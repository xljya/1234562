# 图片上传去重

照片上传入口会在压缩前计算原始文件的 SHA-256。文件名不参与比较：
同内容改名仍然重复，同名但内容不同的文件可以分别上传。
重复项显示“该图片已上传或正在上传，请勿重复上传”，不会发送图片到存储。
批量操作逐张处理，重复和失败不阻断其他图片，完成后汇总三类数量。

## 启用与历史数据

部署代码后，新上传自动启用去重。首次使用会按项目现有的按需建表方式创建
`photo_fingerprints`，数据库账号需要 CREATE TABLE 权限。
该表独立于 `photos`，覆盖待发布图片和已发布图片，不修改已有照片记录。
请在开发/预览环境验证后按自己的部署流程发布。

在后台照片页或上传列表点击“历史图片去重索引”，也可访问
`/admin/fingerprints`，点击“开始补算”。必须使用管理员账号。
工具读取已发布照片（含隐藏照片）及待发布文件，逐个请求补算，展示进度，
失败项可重试。重新打开并执行时会跳过已经关联指纹的 URL。
存储列表支持分页；任何配置中的存储列举失败会明确失败，不把漏读当成完成。

原来存在的多份重复照片全部保留；一个指纹可以关联多份历史文件。
只删除其中一份时，剩余副本仍会阻止重复上传；删除最后一份后允许重新上传。
统计中的“新增重复副本”是本次索引发现的额外副本数，不是删除数量。

历史文件只能对当前存储字节补算指纹。如果曾压缩、清除 EXIF 或转换格式，
无法还原上传前的文件指纹，因此重新选择原图不一定能与旧照片匹配。
本功能不进行视觉相似度判断：重新压缩、裁剪或修改元数据后的文件可能被视为新文件。

## 并发、重试和删除

- 数据库以 SHA-256 为主键，使用原子占用；同一指纹的并发请求只有一个获准。
- 浏览器直接上传到 `pending-<token>.<extension>`，不经过应用服务端转发大文件。
  服务端确认文件存在后复制到 `upload-<token>.<extension>` 并登记成功。
  新格式但尚未登记成功的对象不会展示在待发布列表。
- 完成及取消使用事务行锁和 token 校验；已失效的旧请求不能释放新请求的占用。
  完成响应丢失时可恢复已保存的 URL，避免把成功的上传删除。
- 普通上传失败会删除本次临时对象并释放占用，可以立即重试。
  浏览器直接关闭、服务端/存储无法连接等情况下，未完成占用在 15 分钟后可被新尝试替换。
  极慢上传若超过这个时间且被另一个请求替换，需要重试。
- 正常完成后清理临时文件。进程崩溃或浏览器退出可能留下不可见的临时对象；
  可按存储运维策略为 `pending-` 前缀配置较长生命周期（例如一天）。
  本次实现不会自动修改桶策略，也不会清理已有照片。
- 发布或迁移照片时保留原始指纹关联；通过后台删除图片后释放对应关联。
  在存储控制台或数据库外部直接删除文件不会自动同步指纹索引。
- 原文件哈希来自经过管理员鉴权的浏览器，服务端验证格式并检查上传对象存在。
  它用于正常上传流程去重，不是面向不可信上传者的内容真实性验证协议。

## 验证

普通单元测试（无数据库、存储写入）：

```text
pnpm exec jest --runInBand --watch=false --runTestsByPath __tests__/dedup-client.test.ts
```

数据库生命周期测试使用真实 PostgreSQL，默认跳过，必须显式设置
`DEDUP_TEST_DATABASE_URL`。只接受 `localhost` / `127.0.0.1` 上名为
`dedup_test` 的专用数据库；测试会清空其中的 `photo_fingerprints` 表。
不要指向运行中应用的测试库或任何需要保留数据的库。

```text
pnpm exec jest --runInBand --watch=false --runTestsByPath __tests__/dedup-postgres.test.ts
```

应验证：改名重复、同名不同内容、批内重复、全批重复、并发占用、上传失败重试、
响应丢失、过期请求、发布后重复、删除后重传，以及旧副本全部保留。
真实存储验证记录应注明适配器；仅通过 MinIO 不代表已完成云端 Blob/R2/S3 联调。

### 本次实现验证（2026-09-13）

- 独立本地 PostgreSQL：14 项客户端/数据库测试通过，包括 12 请求并发占用。
- 本地 MinIO + 浏览器：原文件/改名副本/同名不同内容混合上传得到 2 成功、1 重复；
  全批重复被拦截；网络中断后批量继续、恢复后立即重试成功。
- 浏览器验证待发布删除后重传、发布后拒绝重复、已发布删除后重传。
- 两份旧文件补算得到 1 份额外重复副本，两份文件均保留，再次上传被拦截。
- 桌面和 390px 窄屏检查通过，新增页面无横向溢出。
- lint、TypeScript 和隔离配置的生产构建通过。
- 全仓测试仍有 7 个套件被现有 `uncrypto` / `htmlparser2` 的 ESM 解析问题阻断；
  本次未升级相关依赖。Jest 增补了仓库 `@/` 路径映射以运行回归测试。
- 没有对生产数据库执行迁移或历史补算，也没有部署。
